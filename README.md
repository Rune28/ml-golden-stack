# ml-golden-stack

Reference stack for multi-model batch ML pipelines: OpenTofu, Kubernetes, Kueue and Temporal. Runs locally on kind and is designed to run on EKS with the same platform layer.

> Work in progress. The local cluster (`infra/local`) and Temporal (`infra/platform`) are implemented so far.

## Layout

| Directory | Purpose | Status |
|---|---|---|
| `infra/local` | kind cluster provisioned with OpenTofu | ✅ |
| `infra/platform` | platform services as helm releases: Temporal | ✅ Temporal, MLflow and MinIO planned |
| `temporal` | Temporal workflows: pipeline orchestration, model promotion | planned |
| `de_worker` | data engineering worker: video decoding, segmentation, I/O | planned |
| `mle_models` | model steps behind a common batch interface | planned |

## Local cluster

The cluster mimics cloud node groups so that scheduling rules written locally carry over to EKS:

| Node | Pool label | Capacity label | Taint |
|---|---|---|---|
| control-plane | — | — | `node-role.kubernetes.io/control-plane:NoSchedule` |
| worker | `node-pool=cpu` | `capacity-type=on-demand` | — |
| worker | `node-pool=gpu-sim` | `capacity-type=spot` | `nvidia.com/gpu=present:NoSchedule` |

`gpu-sim` has no GPU. It reproduces the labels and taint of a GPU node group so that Kueue flavors, tolerations and node selectors can be exercised locally. Workloads on it run on CPU.

Pools, sizes, labels and taints are configured through the `node_pools` variable.

Services that will be exposed on the host (NodePort → `127.0.0.1`):

| Service | URL |
|---|---|
| Temporal UI | http://127.0.0.1:8080 |
| MLflow | http://127.0.0.1:5000 |
| MinIO console | http://127.0.0.1:9001 |

### Requirements

- [OpenTofu](https://opentofu.org/docs/intro/install/) ≥ 1.8
- Docker (Podman works with `KIND_EXPERIMENTAL_PROVIDER=podman`)
- kubectl
- ~6 GB of free RAM for the cluster and platform services

The `kind` CLI is not required: the cluster is created by the `tehcyx/kind` provider.

### Usage

```bash
make infra-up        # create the cluster
export KUBECONFIG=$PWD/infra/local/.kubeconfig
make infra-status    # nodes, pools and taints
make infra-down      # destroy the cluster
```

The kubeconfig is written to `infra/local/.kubeconfig` (gitignored), so `~/.kube/config` is left untouched.

## Platform services

`infra/platform` is a separate OpenTofu root module with its own state. It reads the cluster connection from the `infra/local` state, so it can be applied and destroyed without touching the cluster.

```bash
make infra-up          # the cluster must exist first
make platform-up       # Postgres + Temporal, first run takes a few minutes (image pulls)
make platform-status   # pods in the temporal namespace
make platform-down
```

### Temporal

| Part | How it runs |
|---|---|
| Server (frontend, history, matching, worker) | official `temporalio/temporal` chart, one replica each |
| Persistence and visibility | one Postgres StatefulSet in the `temporal` namespace, databases `temporal` and `temporal_visibility` |
| Schema | created and migrated by the chart's schema job (pre-install / pre-upgrade hook) |
| Namespaces | `default` with 3 days retention, created by the chart's namespace job |
| UI | http://127.0.0.1:8080 (NodePort 30080) |
| Frontend for workers | `temporal-frontend.temporal.svc:7233` |

All pods are pinned to `node-pool=cpu`. Postgres is a local stand-in for RDS: no replication, no backups. The database password is generated by OpenTofu and stored in the `temporal-db` Secret.

`numHistoryShards` is 4 locally and cannot be changed after the first install without recreating the database (`make platform-down && make platform-up`).

For a quick check from the host:

```bash
kubectl -n temporal port-forward svc/temporal-frontend 7233:7233
temporal workflow list --address 127.0.0.1:7233
```
